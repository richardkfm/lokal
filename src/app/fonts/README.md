# Fonts

Two OFL-1.1 families, committed as files rather than fetched at build time.

`src/app/globals.css` commits this project to builds that work offline and
air-gapped — a realistic constraint for the municipalities and SMEs lokal targets,
several of which build inside networks that cannot reach `fonts.googleapis.com`.
`next/font/google` would break that. `next/font/local` over committed files keeps
it, and still gives Next's preloading and layout-shift handling.

| File                         | Family                           | Subset | Source                           |
| ---------------------------- | -------------------------------- | ------ | -------------------------------- |
| `inter-latin.woff2`          | Inter, variable 100–900          | latin  | Google Fonts `inter/v20`         |
| `jetbrains-mono-latin.woff2` | JetBrains Mono, variable 100–800 | latin  | Google Fonts `jetbrainsmono/v24` |

## Why latin only, with no latin-ext

The `latin` subset covers `U+0000-00FF`, which contains every German character —
`äöüßÄÖÜ` are `U+00E4 U+00F6 U+00FC U+00DF U+00C4 U+00D6 U+00DC`. German needs no
`latin-ext`; that subset carries Central and Eastern European letters such as
`ł`, `č` and `ś`.

Shipping it as well would have added 100 KB to serve glyphs that appear only if
someone types a Polish or Czech name into a free-text intake field. Those fall
back to the system stack for the affected glyph, which is a rare cosmetic
difference rather than a correctness problem. 88 KB total is the trade taken.

Both families are SIL Open Font License 1.1, which permits bundling and
redistribution. The license texts travel with the files, as the OFL requires:

## Replacing or updating

The `@font-face` declarations are generated by `next/font/local` in
`src/app/[locale]/layout.tsx`. Both are declared with a weight _range_, so a
static single-weight file would need that range corrected.
